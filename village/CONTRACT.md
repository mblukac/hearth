# Hearth village implementation contract

Standalone Python package in `village/`, static vanilla ES module frontend. Run from root `python -m village.server`. Server owns mutable simulation, static files, REST API, background updates and persistence. All coordinates are tile units on a 48 x 34 map. No dependencies beyond httpx and python-dotenv already installed.

Engine exports `Simulation(seed=42)`, `.state` dictionary, `.snapshot()` deep copy, `.tick(minutes=5)` move clock/movement/needs, `.decision_context(villager_id)` dictionary, `.available_actions(villager_id)` list of action descriptors, `.apply_decision(villager_id, decision)` event or None, `.apply_narrative(villager_id, narrative)` and `.apply_oracle(event)` event. Optional `.from_state(state)` classmethod. Engine owns data/personas/actions. Do not perform API calls inside engine.

State keys: `version`, `seed`, `tick`, `day`, `minute` (minutes since midnight), `weather`, `season`, `villagers` list, `locations` list, `events` newest-first list, `world` dict (prosperity, tension, dread all 0-100; food, treasury numeric), `contexts` list. Server adds `running`, `speed`, `mode` (live/demo), `providers`, `metrics`, `action_catalog`.

Villager: `id`, `name`, `age`, `gender`, `pronouns`, `occupation`, `backstory`, `traits` dict, `values` list, `goal`, `color`, `skin`, `hair`, `x`, `y`, `home` location id, `workplace` location id, `action` action id, `action_label`, `target_id` nullable, `destination` nullable {x,y}, `needs` dict (energy,hunger,social,safety all 0-100, higher=more fulfilled), `mood` string, `thought` string, `speech` string, `relationships` dict keyed other id with {affinity,trust,romance,status}, `memories` newest-first [{id,day,minute,text,emotion,importance}], `decision` nullable {action,target_id,think,speak,confidence,probabilities,source}, plus demographics object and optional pregnancy/family. ALL initial 20 villagers adults. Intimacy/family planning abstract non-graphic, mutual adults only, children never romantic candidates.

Location: `id,name,type,x,y,w,h,color` rectangle. Event: `id,day,minute,type,text,actor_id,target_id` (optional text source). Oracle event: `{text,kind,intensity,duration_hours, effects:{dread,tension,prosperity,food,weather}, source}` effects numeric changes except weather string; kind among atmosphere,threat,abundance,scarcity,celebration,politics,weather; intensity 0-100. Contexts carry text, kind, intensity, expiration.

Decision: `{action: action_id,target_id: id|null,think:bool,speak:bool,confidence:float,probabilities:dict,source:'jev'|'demo'}`. Action descriptors: `{id,label,category,description,...}`. Provider `ModelGateway` synchronous methods `.decide(context,actions)->decision`, `.narrate(context,decision)->{thought,speech,source}`, `.interpret_oracle(text,intensity=60,duration_hours=24)->oracle event`, `.status()->dict`, `.metrics` dictionary; `.demo_decide(context,actions)` and `.demo_narrate(context,decision)` deterministic fallback helpers if useful. Constructor no required args, loads root `.env` without exposing secrets. Network errors raise safe exceptions (no silent demo fallback). Gateway mode managed by server. Jev decisions use full valid action candidates; Luna low reasoning for fictional thoughts and speech. Context supplied by engine includes actor, nearby villagers, world, contexts, locations, clock.

API: GET `/api/state` snapshot; GET `/api/events` {events}; POST `/api/control` {running?:bool,speed?:1|2|5|10,mode?:'demo'|'live',step?:true}; POST `/api/oracle` {text,intensity:60,duration_hours:24}; POST `/api/villagers/<id>/nudge` {action:'think'|'talk'|'go_home'}; POST `/api/save` {}; POST `/api/reset` {seed:42}; GET `/api/export` download JSON. All POST return state snapshot unless specified. Errors {error:string}. Frontend polls state ~1s. Start paused in live mode if credentials exist, otherwise paused demo; server on 127.0.0.1:8765, protect mutations against cross-origin requests. Model work background/worker thread and never while holding state lock. Root handles server and integration tests, other agents exclusively own engine+data, providers, or frontend files.

Scenario lifecycle: POST `/api/oracle/<id>/update` accepts the same fields as creation and replaces the active scenario. POST `/api/oracle/<id>/dismiss` accepts `{reason?:string}` and ends it without model inference. Unknown or already ended targets are rejected before billing. Engine exposes `.replace_context(id,event)` and `.dismiss_context(id,reason='')`; active influences stay in `contexts`, ended scenarios move to bounded `scenario_history` with `status`, `ended_at`, and `resolution`. Old memories remain, marked with their context status, and every villager learns the resolution. Decision contexts include recent scenario history. Narratives carry `context_ids` so the engine can reject stale effects after a scenario ends. Server generation invalidation also guards in-flight results. Oracle interpretation tracks reset/mode changes and target validity separately so unrelated scenario expiry does not waste a paid interpretation.

Snapshots include `server_instance` and a monotonic `revision` per process to order concurrent polling and mutation responses even while the simulation is paused. Scenario mutations save immediately.
